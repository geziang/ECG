## Git 进一步减负建议

1. **现阶段保留复算证据在仓库内。** 当前 `.git` 约 62.49 MiB，不存在需要通过重写共享历史解决的体积问题；ZIP 已压缩，继续打包的空间收益有限。
2. **未来新增大型实验产物先确定归档规则。** 原始数据、特征和权重继续在 Git 外；小型协议、表格、预测顺序、配置/哈希和必要预测证据入库。若将来预测归档增长到 GB 级，再设计外部版本化存储、下载清单和完整性校验，迁移完成并验证独立复算后讨论旧历史处理。
3. **代码清理另开明确范围。** `get-pip.py` 在 HEAD 中约 2.12 MiB，本地搜索未见项目调用，可作为后续删除候选，但应先核对环境搭建流程；本轮未删。历史实验脚本应先查调用与报告依赖，再判断是否移入历史目录。
4. **暂不清理失效 worktree 注册。** 检测到 `ECG_trc_insertion_ablation` 的旧注册指向不存在位置，但元数据还含 index/refs。核对其 Git 状态与恢复价值之后再处理；本轮没有运行 prune 或删除分支。
5. **工作区外层稿件单独安排备份。** 当前 Git 根是 `ECG/`，根目录的 V7、V6、Word 和最终图集不在该 Git 根内；整理 Git 不代表这些文件已经备份。不要为追求一个干净的根目录而扩大 Git 根或直接搬动稿件引用路径。
