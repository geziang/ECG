## 3. A1：数据契约与测试集隔离

主任务固定为 CPSC 原始九类 multihot。类别顺序：`NSR, AF, IAVB, LBBB, RBBB, PAC, PVC, STD, STE`。训练/验证沿既有记录划分，预期 train=4809、val=683；按源清单审计 test 元数据=1385，**本批训练进程不获得测试信号或标签路径**。当前真值 CSV 中训练多诊断 343 条、验证多诊断 36 条，作为元数据检查，不把少量多诊断验证记录单独作为选线主终点。

- 每条记录用 record ID 关联信号、多标签、旧主类和 split；不按文件排列猜标签。跨 split ID、重复信号哈希、标签维度与类别顺序必须检查；同内容哈希不等于患者去重。可靠患者 ID 若缺失，注明 record-level 限制；发现患者交叉则先报告并停止相关比较，不静默重划分。
- 本地 LP/表示诊断使用既有 8 导联顺序 `[II,III,V1,V2,V3,V4,V5,V6]`、float32 `(8,2048)`、有效采样率 204.8 Hz 和现有全记录逐导联 z-score。先查预处理来源与值域，防止二次归一化；本批不改导联数、不添加随机噪声/裁剪增强。
- 任何总体均值/方差和可学习归一化只由训练划分估计；逐记录预处理按已冻结规则。旧辅助目标“全库统计”不能误用为新的下游 train+val+test 统计。
- HeartLang 保留作者预训练输入及 QRS/token 约定，使用相同 CPSC record ID、multihot 和 split。原生信号路径、采样率、导联、截取范围须另记，不能从已归一化的 8 导联随意拼造 12 导联。原始输入缺失时暂停该支线。
- 把 train/val 数据导出到独立适配目录，文件名/顺序与标签共同锁 SHA256。作者自动重划分、全量拟合 scaler、根据 test 最大长度设置网络或预载 test 的逻辑不得进入开发入口。
- 源真值 CSV 含全部 split；准备程序仅按 split 导出 train/val，test 仅使用既有 record ID/split 元数据核对身份与数量，不分析其诊断列。源文件的按字节哈希校验与测试标签分析分开；开发子进程只获得导出的 train/val 文件，不能接收完整真值 CSV 后自行访问 test。
- 从源清单核验 test 的数量/身份/已有划分哈希属于准备审计；不读取其 ECG 内容或计算新模型分数。不能宣称历史 CPSC test 从未使用过。

## 4. A2：本地冻结编码器的多标签 LP（9 作业）

M0/M4/M6 × seeds `{0,2,4}`。每行的 `pretrain_seed=head_seed=s`，明确种子同时索引历史编码器和新分类头，不声称单独分离了两种随机性。

- 只读原 checkpoint；编码器 `eval`、冻结全部参数，缓存训练/验证 512 维逐记录特征，带 record ID、顺序、权重/预处理/代码 SHA。允许复用已核验的 train/val 特征缓存，不能因文件名相同就跳过来源核对；不加载 `X_test`。
- 训练一个 `Linear(512,9)`。标准 `BCEWithLogitsLoss`，无类别权重，sigmoid 输出；不对概率使用 softmax，不把 multihot 压回主类。
- Adam：lr=0.001、betas=(0.9,0.999)、eps=1e-8、weight_decay=0；batch=128、最大 100 epoch、patience=15；无 scheduler、增强、dropout 或超参搜索。最后不足批保留。验证损失按样本与类别总元素加权；严格最小验证 BCE 保存，平局保留更早 epoch。全部首批训练用 float32。
- 首先完成三个 seed0 格子的工程检查；通过后补所有 seed2/4，不依据 seed0 的涨点决定是否补齐。A2 完成不要求任何模型排序。

## 5. A3：心拍表示诊断（4 配置 × 3 种子 = 12 作业）

这是**借鉴参考模块的受控表示实验，不是 tokenizer 论文数值复现，也不是 LFBT 预训练增量实验**。为避免不同 tokenizer 的检测器、窗口、前端维度和主干同时改变，第一批使用统一分片与轻量网络。

### 5.1 统一分片

- 对同一 train/val 记录离线建立峰缓存：`gqrs_detect`，fs=204.8，先 V5（当前 8 导联 index6），不足 4 峰回退 II（index0）；核对 WFDB 实际版本和参数并冻结。只检测增强前记录。该检测输出不是人工峰真值。
- 每个心拍取 W=205 个样点，中心 p，范围 `[p-102,p+103)`，越界沿用旧实现 edge padding；不做每拍独立重归一化。有效峰数至少 4，最多保留 K=16；超过 16 按有序峰索引等距、确定性取 16 个，四个配置共享同一保留集合。
- `K_r=min(有效峰数,16)`，四配置同一记录使用相同 `K_r` 个有效槽与 mask，补至 16；总是计算完整 16 槽。少于 4 峰的记录四配置均回退到 16 个均匀固定窗，保留记录并标记 `beat_valid=false`，禁止过滤后只报优势样本。

| 配置 | 输入构造 | 回答的问题 |
|---|---|---|
| D0 matched_fixed | 在全记录中均匀放置 `K_r` 个 W=205 窗 | 匹配窗长、窗数和容量的非峰对齐对照；它共享峰计数，不冒充完全不使用峰信息的模型 |
| D1 mean_template | 对保留的 `K_r` 个真实心拍窗求平均，将模板复制到相同有效槽 | 当前平均压缩方式 |
| D2 median_template | 对同一心拍窗集合逐点取中位数，复制到相同有效槽 | 简单强模板对照 |
| D3 beat_set | 同一 `K_r` 个心拍窗分别编码后 mask 均值聚合，无位置编码、无 RR 输入 | 保留逐拍变化的无序集合；不将其收益解释成节律顺序贡献 |

统一窗口/掩码适配参考 `models/tokenizers/median_beat.py`、`heartlang.py` 与本地 `beat_view`，记录源 commit 和差异。本批不直接使用作者 xqrs/导联默认值与自己的 gqrs 混做分片比较。

### 5.2 同一小型网络与训练预算

所有配置相同的共享窗编码器：`Conv1d(8,32,k7,p3,bias=True) → ReLU → AvgPool1d(2) → Conv1d(32,64,k5,p2,bias=True) → ReLU → AdaptiveAvgPool1d(1)`；在有效槽上均值聚合后接 `Linear(64,9)`。无 BN、dropout、注意力或位置编码；共 12,713 个可训练参数，A 机须独立计数核对。

四配置从头监督训练该小模型，仅用于信息诊断；与 A2 的冻结大编码器结果分表，不据两表绝对数字宣称新 SSL 方法胜负。训练损失、优化器、batch、epoch、早停规则与 A2 相同。seed0 工程检查通过后补 `{2,4}` 全部配置，不择优补种子。64 条训练记录的有限过拟合检查、mask/边界/无峰回退检查先于主作业；若小模型明显未学会训练任务，不能把负结果解释成逐拍信息没有价值。

### 5.3 峰位置敏感性（仅验证推理，不增训练作业）

对同一已训练模型，验证峰位置附加确定性扰动：原始、均匀整数偏移 ±4、±8 样点（约 ±20/40 ms）。同记录、扰动档和固定 seed=20261023 生成共享偏移；保持保留峰数和有效槽不变，边界裁到 `[0,2047]`。D0 输入保持不变，其他配置按扰动峰重新构造。保存逐记录配对输出。

这只测峰定位扰动敏感性，不代表已测真实漏检/错检率、临床噪声鲁棒性或可靠性估计准确度。本批不扫描噪声 SNR、不训练质量门控、不因异常波形偏离正常模板而排除样本。

当前是记录级诊断任务，没有已核验的逐拍病理真值。因此即使 D3 优于模板，也只能先支持当前条件下的表示价值，不能直接声称发现或保留了哪一个异常心拍。

## 8. 指标、选线门与停止规则

本批主开发指标为验证 macro-AUPRC，辅以 macro-AUROC、逐类 AP/AUROC、类支持数、验证 BCE、单/多诊断及峰有效性分组。所有类保留，不删除低分/罕见类别；无定义指标显式标 N/A 并说明，不能悄悄改变宏平均分母。本批不调 F1 阈值、不报告新的测试结果。

工程性选线比较只在 D0–D3 内进行。先按三种子平均验证 AUPRC 在 D0/D1/D2 中固定最强简单对照，再算 D3 配对增量。进入逐拍后续研究的建议条件：均值 ≥0.005、3/3 为正，且验证阳性数≥20 的类别没有平均 AP 下降超过0.02。阈值仅用于研究预算筛选，不是统计显著或临床有效性声明；不在结果出来后放宽。峰扰动只作配对敏感性描述，不额外据其扫描参数。

- 标签/来源 SHA 不符、test 被访问、权重错配、样本顺序不一致、损失非有限或冻结权重改变：相关阶段停止，写事件，不输出可用结论。
- OOM：先核验独占 GPU；不能静默改 batch、输入长度或导联。若仍不满足，报告该行未完成，不用缩水配置替代正式行。
- 工程故障最多一次有记录的修复/恢复；超出则暂停该行并回传。能从相同配置完整 checkpoint 恢复时，保存优化器/epoch/RNG/数据顺序，不把恢复当新 seed。
- 阴性或无提升是有效结果；不追加损失、种子、标签比例或超参搜索。首批完成只取决于交付与正确性，不要求涨点。
- 同一唯一键只认协议、权重、数据、代码哈希均一致且产物完整的结果；不能以“有 checkpoint”为完成。预算用尽/缺件写 partial，不伪填数字。
