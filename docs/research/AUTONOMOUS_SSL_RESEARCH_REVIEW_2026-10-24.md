## 1. 结论与当前缺口

有限范围的自动实验可以实现：协议、配置及分支固定后，自动完成预检、训练、验证、复算、补种子、停止和报告。其完成结果也可以是阴性或未完成，不要求不断创造新方法直到涨点。

当前总清单仍有科学设计缺口：Q13–Q16的新自监督目标、视图对应、参数范围和预算没有冻结；P0及拟议整段—局部融合诊断属于使用诊断标签的下游评估。它们可以辅助选线，不能代替新SSL预训练实验。不能把当前20项规划描述成已可连续无人值守执行的成熟程序。

本轮只做定向查阅和代码核对，尚未完成穷尽查新、所有相关论文精读或新候选的数值复现。已有证据支持有针对性地检验假设，尚不足以承诺新颖性与有效性。

## 3. 沿用什么自监督路线

当前代码与冻结协议提供明确基础：

- `run_pt.py` 的主目标保持同导联/跨导联两视图的Barlow Twins；M6为TRC+NSTDB噪声背景。原NFH协议为100epoch，不能把任意短pilot与历史完整权重作同预算比较。
- 旧Beat-RR通过共享编码器处理平均心拍，加入整段—模板一致性与信号导出的RR统计回归；这些目标来自信号，不需要下游诊断标签。
- 预训练不得读取CPSC/PTB-XL下游验证或测试标签；下游BCE线性头训练是评价步骤，需与预训练数据/梯度路径分开。

建议保持的研究路径是：**无标签信号与冻结生理处理 → 同背景/同预算自监督预训练 → 丢弃训练辅助分支 → 冻结编码器、同协议LP/少标签微调 → 机制反事实与外部验证**。

关键的新增验证：如果优势只在下游保留新增局部分支时出现，移除该分支后原编码器没有正向增量，就只能报告下游融合收益，不能写成自监督表征已经改善。

## 4. 从“有依据”到“不是盲撞”还需要什么

历史[失败索引](../../ECG_SSL_LFBT-main/runlog/W3/failed_directions_index.csv)的E003记有“自动复合验证过拟合”；弱裁剪也曾出现seed0正、后续种子负。它们是本项目已知经验，不能忽略后再启动无限模块组合。

未来每个候选必须先写五项：

1. 从哪个本地观测提出假设；它不能只是“论文用了这个模块”。
2. 论文已经覆盖哪些部分；本候选具体剩下哪个待验证差异。
3. 什么预训练信号会改变共享编码器，是否依赖人工诊断标签。
4. 哪个容量/窗口/增强匹配对照和反事实能推翻解释。
5. 每批候选数量、固定参数、种子、训练步数及预算上限；阴性后结束该批。

正向阈值仍按用户偏好取0；同时限制搜索数量并完整记录所有运行。零阈值允许给正向信号后续验证机会，不允许反复改权重、种子和指标直到出现一个正数。反复优化有限验证集也可能造成选择偏差，见[Cawley与Talbot的模型选择研究](https://www.jmlr.org/papers/v11/cawley10a.html)。

## 5. 一个有边界的SSL实验框架（不是已批准的新算法）

现阶段可讨论的机制假设是：平均心拍可能抹去有用局部变化；局部先验的不确定性也可能产生错误约束。但P0逐拍集合未占优，且轻微峰平移影响较小，**目前没有直接证据证明“峰可靠性是当前主要瓶颈”**。原生复现、互补诊断和预训练语料上的峰处理审计应先于该机制升级；只看轻微抖动不能推断漏检/错检鲁棒性。

若上述证据支持该问题，一批可预先定义为以下组别；候选只能选一个，配套对照先写完后启动：

| 组别 | 预训练身份 | 回答的问题 |
|---|---|---|
| S0 | 重新匹配训练的M6背景 | 无新增局部约束时的基线 |
| S1 | 同背景+旧Beat-RR | 是否只是重复已有辅助目标 |
| S2 | 同背景+固定窗局部目标 | 容量、额外前向与观察窗能否解释变化 |
| S3 | 同背景+均匀权重的逐拍局部目标 | 逐拍训练信号本身是否有效；属于方法参照，不能预先当作创新 |
| S4 | 同S3，仅改变已经明确定义的先验使用机制 | 候选的单一机制是否带来额外价值 |
| S5 | 候选机制的对应负对照 | 如重排可靠性权重且保持分布，检查是否真与对应心拍有关 |

如果候选不是可靠性机制，S4/S5须改为该候选的真实处理与对应反事实。按用户后续澄清，允许多个相关候选及组件组合分轮试验，具体候选数与预算见最新增量计划；不要求每个候选先具备独立创新性。实际改动和选择过程须完整记录。

损失结构可以保留 `L = L_LFBT + eta * L_local` 作为接口草图，但`L_local`的正对/负对或预测目标、共享参数、stop-gradient、失效回退、eta与损失归一化都尚需定义。仅写总损失形式不等于有了新算法，不据此下发训练。允许复用既有处理逻辑，不重新扫描已关闭的VICReg/重建/LCM等轴。

所有组使用同一预训练split、相同基础初始化规则、相同数据量和训练步数。先跑冻结预算的短pilot，只与同样短训的基线配对；正式训练全部补齐固定种子。每组按相同方式移除辅助头，仅用共同编码器及相同下游头评价；用户的正向继续门在此仍为固定主验证指标配对均值>0。

## 6. 无人值守应怎样落地

| 层次 | 负责内容 | 允许自动决策 |
|---|---|---|
| 工作机执行器 | 固定环境/代码快照、队列、GPU锁、checkpoint与资源记录 | 预检、运行、从完整状态续训、验证、复算、按冻结分支补种子或结束 |
| 结果审查器 | 检查参数/数据身份、运行有效性、全部结果与失败记录 | 修复一次已定位的工程故障；不可修改损失、划分、科学参数或篡改完成标记 |
| 办公机巡检 | 读取Git回传的状态、报告和异常 | 仅在完成、失败、达到预算或需要外部动作时通知；无变化时保持安静 |

工作机执行器与办公机巡检分别运行；Git用于任务与结果交接，不能据一个Git提交就假定远端进程已启动。当前仍遵循只走origin/main、不使用SSH跨机操作。若需要在工作机代码变动，使用独立固定副本，不在运行中的目录checkout/rebase。

建议队列状态：`PLANNED → VERIFIED → RUNNING → TRAINED → EVALUATED → RECOMPUTED → COMPLETE`；异常为`FAILED/INCOMPLETE`，科学阴性为有效完成并结束对应分支。只有全部产物与身份检查通过才能标COMPLETE。

真正断点恢复保存模型、优化器、scheduler/scaler（若使用）、epoch/step、RNG、采样器/数据顺序与数据身份。仅有best checkpoint只能做评价或按明示规则从头重跑，不伪装成连续训练。重试次数与已消耗资源计入总账。

科学分支不需用户逐项盯：门与预算已固定的步骤自动推进；所有假设未获支持时自动出阴性报告。需要新数据权限、超出预算或改变已冻结研究范围时，结束当前批次并报告具体缺口，不能自行无限扩展。
