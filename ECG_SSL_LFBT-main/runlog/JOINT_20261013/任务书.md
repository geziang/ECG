## 二、重大发现:A1/A2 seed0 R 峰缓存错配 → 三种子全部重跑

**证据链**(2026-10-13 主机A核验):

1. `checkpoint/w8_dvsplit/{dvo,rro}_seed0/config.json`:`rpeak_npz = "data/pt_rpeaks.npz"`——是 run_pt 默认值;W8 E5 链脚本 `runlog/W8/run_e5_e7_chain.py`(L109-115)命令模板**漏传 `--rpeak-npz`**;
2. `data/pt_rpeaks.npz` = **17,418 条 = 旧 PTB-XL 预训练语料**的缓存(`runlog/prep_rpeaks.py` 默认 `--data-dir data/pt_pretrain`);NFH 全量 34,905,键按 `sample_XXXXX` 位置编码 → 前 17,418 条 NFH 记录拿到**另一语料信号上检测的 R 峰索引**(心拍视图错位、RR 目标错值),后 17,487 条无键(valid=0,辅助损失不参与);
3. 对照组:M2 三种子 config 均为 `pt_rpeaks_nfh.npz`(34,905,与 NFH 一一对应,preflight 已核验)。

**后果**:W8 E5 的"单双视角/单RR 均 cpsc 0.9444 ≈C1−0.19pt,联合增益=双组件协同"结论建立在**全错辅助目标**上——模型只是学会了忽略垃圾目标,该 4 行数字不可用于组件消融表(protocol §10 表 2)。两臂 AUROC 同为 0.9444 亦与此解释相容。

**裁决**(protocol §2 "若发生代码错误,只允许修复实现"):

- A1/A2 由"补 s2、s4"改为**三种子全部重跑**,显式 `--rpeak-npz data/pt_rpeaks_nfh.npz`;最低新增 PT 量 10 → **12 次**(+M6 可选 3 次 = 15);
- `runlog/W8/w8_dvsplit_results.csv` 为冻结账本**只读不动**;在 `runlog/W8/events.md` 追加更正记录(不删行);W8 最终报告(待写)须引用本更正;
- 污染 checkpoint 留盘不入库(checkpoint/ 本就不入 git);
- M2/M3 与 A1/A2 的可比性声明:M2 用对缓存,M3/M4/A1/A2 本批次全部用对缓存,组件消融表五臂(M0/A1/A2/M2/M3)口径统一。

## 四、命令模板(逐字,SEED ∈ {0,2,4};与锚点逐字对齐处已标注)

```bash
  --rpeak-npz data/pt_rpeaks_nfh.npz --resume \
  --checkpoint-dir checkpoint/joint_m3/seedSEED
```

**A2** 同型:`--dualview-weight 0 --rr-weight 0.1`,dir `checkpoint/joint_a2/seedSEED`。

**LP**(`--trc` 与预训练一致;W8 E6 同型):
```bash

  --checkpoint checkpoint/NAME/seedSEED/encoder_group.pth \

  --seed SEED --workers 6 --trc TRCFLAG --extended-metrics 1 \
  --save-predictions runlog/JOINT_20261013/predictions/NAME_DOM_lp_seedSEED \
```
